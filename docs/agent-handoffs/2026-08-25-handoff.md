## Gotchas noted this session

- **Bash tool working-directory resets**: a couple of times this session, after a command was blocked by the permission classifier (see below) or otherwise failed, the next `Bash` call landed back in the repo root instead of the `backend/` directory a `cd` had previously established. Not fully diagnosed — just verify with `pwd` rather than assuming `cd` persistence held, especially right after a blocked/denied command.
- **The permission classifier blocked a read-only inspection of `.env`'s secret content** (checking `RAZORPAY_KEY_SECRET` for stray whitespace/quoting via a Python one-liner that printed only metadata like length and character classes, not the value itself) — flagged as touching credential file contents. Worked around by asking the user directly rather than pushing further; they fixed the credential and the live check then passed. If a future session needs to debug `.env` values, expect this same guardrail and go straight to asking the user rather than iterating on inspection commands.
- Carried over from the previous handoff, still relevant if doing manual/live backend testing outside a ticket's own automated suite: `EnterWorktree`'s default `baseRef` is stale for this repo (use `git worktree add -b <name> <path> master` manually, per the 2026-08-24-01 handoff); a backgrounded `uvicorn` stopped via `TaskStop` may leave an orphaned `python.exe` still holding the port (`netstat -ano` + `Stop-Process -Id <pid> -Force`).
