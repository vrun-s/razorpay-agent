## Two things learned the hard way in the 08/09/10 session — still apply

1. **Before choosing any numeric constant in `decision.py`/`estimator.py`/`allocator.py`, deliberately check it against `app/simulator/personas.py` and `app/simulator/response_curves.py`'s actual values first, specifically to make sure it *doesn't* match.** Caught twice this project: `FATIGUE_DECAY_RATE` in ticket 06 (code-review caught it), and ticket 10's `_DEFAULT_RESERVE_RATIO` coincidentally matching `Persona.LOYAL: 0.30`/`0.25` weights (code-review caught it again; fixed to `1/3`). ADR-0007's independence rule technically scopes to the estimator, but the same discipline is worth applying to any new tunable constant in 11–18 (e.g. ticket 16's ±20% perturbation ranges).
2. **Keep commit messages short (1-3 lines body).** Established in memory `feedback_concise_commit_messages` and followed for tickets 08-10 (see `git log` above) — keep doing this.
