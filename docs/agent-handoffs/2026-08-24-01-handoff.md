## Manual testing performed this session (live, against a running server)

Beyond the automated suite, the ticket 12 work was verified against a real running instance:

1. **Full engine flow**: started `uvicorn` from `backend/` with `RAZORPAY_WEBHOOK_SECRET` set, POSTed a correctly-HMAC-signed synthetic `subscription.halted` payload to `/webhooks/subscription-halted`. Confirmed the response case walked through `case_created → decision (resume_charge) → policy_check (approved) → allocation_check (funded) → execution (Gateway resumed charge)` in one call.
2. **Cross-workflow rejection at `/override`**: the automatic decision path never proposes an invalid intervention (already restricted by `VALID_INTERVENTIONS`), so the only way to exercise the new Policy Engine check live is via `/cases/{id}/override`, which only accepts `escalated` cases. The live server's default `PolicyConfig.escalation_value_threshold` is `None`, so nothing auto-escalates — had to force a case's status directly in `recovery.db` via `sqlite3`/Python to reach `escalated`.
   - **Gotcha**: SQLAlchemy stores `StrEnum` columns by the enum's uppercase **name** (`ESCALATED`, `HALTED_SUBSCRIPTION`), not its lowercase `.value` — a naive `UPDATE ... SET status='escalated'` throws a 500 (`LookupError` deep in SQLAlchemy) on the next read. Use the uppercase name.
   - Confirmed both directions: `payment_retry` override on a `halted_subscription` case → `400`; `resume_charge` on the same case → `200` (accepted, case reopened); `resume_charge` override on a `failed_payment` case → `400`.
3. **Worktree gotcha**: `EnterWorktree`'s default `baseRef` is `fresh` (branches from `origin/<default-branch>`), which for this repo is stale (`origin/master` only has up to ticket 02 — 11+ local commits never pushed). Had to exit that worktree and manually create one with `git worktree add -b <name> <path> master`, then `EnterWorktree path=...` to enter it, to get a worktree with the full local commit history. **Do this again for any future ticket if using worktree isolation.**
4. **Process-cleanup gotcha**: stopping a backgrounded `uvicorn` dev server via the `TaskStop` tool did not reliably kill the underlying child process on Windows — an orphaned `python.exe` was found still listening on the test port during a later demo, causing a confusing false-positive health check. Fix: `netstat -ano | grep ":<port>"` to find the PID, then `Stop-Process -Id <pid> -Force` (PowerShell) if `TaskStop` doesn't actually free the port.
5. Merging: after manual verification, the user explicitly asked to fast-forward-merge `ticket-12-halted-subscription` into `master` (not done automatically/autonomously — confirmed via an explicit question first, consistent with this repo's direct-to-master convention). The worktree and its branch were deleted afterward (`git worktree remove` + `git branch -d`) since the merge was a clean fast-forward.
