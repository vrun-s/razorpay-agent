# Budget allocation ships with a flat incentive-response model; learnable discount-sensitivity is deferred

The Policy Engine and Streaming Allocator have carried incentive plumbing (`ProposedIntervention.incentive_amount` / `discount_pct`, `AllocationCandidate.incentive_amount`) since ticket 05, but [[0010-policy-engine-validate-contract]] disclosed that nothing in the live flow ever sets a non-zero cost — `app/lifecycle.py` builds `ProposedIntervention(intervention=intervention)` with no economic terms. So `BudgetLedger.spent` never moves, `available` / `reserved` are flat lines on the dashboard, and the reserve mechanism [[0003-streaming-allocation]] requires has nothing to ration. Making the budget real needs two things: an intervention that costs money, and that cost buying higher recovery odds. The second is the hard part — `app/simulator/response_curves.py` is frozen under [[0007-evaluation-integrity]] (`SIMULATOR_VERSION`) and models recovery probability on `(persona × intervention)` only, with no incentive dimension anywhere in the simulator ground truth or the estimator.

**Decision**: ship the flat model now.

- **Incentive** (new CONTEXT.md term) — a merchant-funded discount bundled with an existing `PAYMENT_RETRY` / `RESUME_CHARGE` attempt, **not** a new `Intervention` enum value. `NO_ACTION` never carries one.
- **Cost.** `incentive_amount = round(case_value * incentive_pct)`, `incentive_pct` a knob on a new unified `MerchantConfig` object (default `5.0`, numerically matching `FIXED_RULE_DISCOUNT_PCT` but kept as an independent constant — [[0013-evaluation-metric-baselines-contract]] owns the fixed-rule rate).
- **Response.** The simulator gains a single flat uplift: any executed intervention with `incentive_amount > 0` gets `+INCENTIVE_UPLIFT` added to its post-fatigue probability (default `0.10`, clamped to the existing `_MIN_PROBABILITY` / `1.0`), applied uniformly across all personas. `SIMULATOR_VERSION` → `response-curves-v2`.
- **No estimator change.** `EstimatorCellKey` gains no incentive axis. The Decision Engine stays greedy on intervention choice ([[0006-decision-engine-estimator]]) and proposes the incentive by a fixed rule — whenever `INCENTIVE_UPLIFT > incentive_pct` (EV-positive by construction with the defaults) — never a learned one.
- **Allocator gates the incentive only.** The base attempt always executes when policy-approved; when the Streaming Allocator declines to fund the incentive, the same intervention runs with `incentive_amount = 0` (degrade to a free retry) — not `NO_ACTION`, not a silent skip as the code does today.
- **Budget unification.** `PolicyConfig.recovery_budget` and `BudgetLedger.recovery_budget` — two independently-configured copies of one number, flagged in `app/allocator.py` — collapse behind the one `MerchantConfig`.
- **Evaluation.** The `ai_treatment` arm carries the same case-value-scaled incentive cost as `fixed_rule` (same `pct`); only intervention choice and allocator funding differ between arms, so budget/policy governance stays a non-confound per [[0013-evaluation-metric-baselines-contract]].
- **Scope: `FAILED_PAYMENT` only.** `HALTED_SUBSCRIPTION` `case_value` resolves to `0` (no Plan-amount lookup), so `RESUME_CHARGE` incentives compute to `0` and that workflow stays outside the budget game — consistent with the eval harness already defaulting to `FAILED_PAYMENT`.

**Considered and deferred — the learnable version.** Making "the agent learned which customers are discount-sensitive" a true statement requires un-freezing the simulator with per-persona uplift curves *and* adding an `incentive` axis to `EstimatorCellKey` (doubling cells against a fixed 300-case dev split, risking thin convergence and a contrived-looking demo), plus a new economic sub-decision in a Decision Engine [[0006-decision-engine-estimator]] deliberately kept greedy. For a solo builder that is a ~5× blast radius across tickets 02 / 05 / 06 / 07 / 08 / 10 / 15 / 18, and it forces regeneration of the committed held-out `evaluation_report.json` with a real chance the numbers come out *less* clean. The flat model makes the Reserved Budget mechanism genuinely demonstrable — a `recovery_budget` set below total incentive demand forces the allocator to decline mediocre cases and fund better ones later — at a fraction of the cost and risk. Layering the learnable response on top is the intended follow-on **if demo time allows**; this ADR would then be superseded in part. Check per-cell observation counts on the dev split before committing to that narrative.

**Consequences**:

- **The pitch/demo narrative must not claim the agent learns discount-sensitivity.** The honest story is budget pacing under a reserve: the agent funds incentives where expected Net Recovered Revenue justifies the spend, holds back the reserve for better arrivals it cannot foresee, and declines mediocre cases rather than exhausting the budget early.
- `SIMULATOR_VERSION` → `response-curves-v2` invalidates comparability with any pre-existing `evaluation_report.json`; regenerate dev + held-out and re-commit as part of this work.
- `INCENTIVE_UPLIFT = 0.10` and `incentive_pct = 5.0` are model constants — part of the system under test, so they apply identically to the evaluation harness and the demo. Defaults, not constraints: tune during implementation, but record any change as deliberate against this ADR, per [[0013-evaluation-metric-baselines-contract]]'s precedent.
- **The demo `recovery_budget` and case-ordering are walkthrough-only tuning.** The demo-seed script deliberately sizes `recovery_budget` below total incentive demand and orders a low-quality case before a high-quality one so the reserve mechanism is visible in a 3–5 minute walk. The evaluation harness must not read that tuned value or seed — it keeps its canonical `MerchantConfig` budget and `DEFAULT_DATASET_SEED` split, with its own fresh per-arm allocator instances as today. Any change that lets a demo knob reach an eval run is a regression against [[0007-evaluation-integrity]].
- `BudgetTimeline.tsx`'s amber "no spend in the live flow" disclaimer comes out once spend is real.
