# Hosted demo ships as one container on Render with the fake LLM, an ephemeral re-seeded DB, and the sweep off

The submission now requires all four of: pitch video, repo, working run instructions, and a **live URL**. That last item was previously undecided ([[0008-tech-stack]] committed only to a local `ssh -R` tunnel for real-Razorpay dev). The app as built is a two-process local setup — FastAPI on `:8000`, a Vite dev server on `:5173` with hardcoded CORS between them, `VITE_API_BASE_URL` defaulting to an absolute `localhost:8000`, and an in-process `asyncio` sweep ([[0005-hybrid-reassessment-trigger]]) that drives Reassessments and therefore LLM calls on a 300s loop. None of that survives a single-container public deploy unchanged, and a public URL running a real `ANTHROPIC_API_KEY` means the sweep spends the key continuously for as long as any case is open, for anyone who finds the URL.

**Decision**: collapse to one process, ship it as one container on Render, and make the hosted instance a fixed, read-only replay.

- **One-port collapse (do regardless of hosting).** Add `server.proxy` to `vite.config.ts` so `vite dev` proxies an `/api` prefix to `:8000` (HMR preserved). Frontend API base becomes `?? ''` (relative), so the bundled build hits its own origin. FastAPI mounts `StaticFiles(directory=<frontend/dist>, html=True)` at `/`, guarded by a dir-exists check so backend-only `pytest` runs still import cleanly. The CORS middleware moves behind a dev-only flag — the hosted path serves UI and API from one origin and needs none. A `run.sh` (or `justfile`) exposes `setup` / `seed` / `dev` / `demo` / `test`.
- **Container is the deploy unit.** Multi-stage Dockerfile: Node build stage produces `dist/`, copied into a Python runtime stage; `CMD` runs `app.demo_seed` then `uvicorn`. `.dockerignore` included. Defaults: `GATEWAY_BACKEND=fake`, no keys, SQLite at an ephemeral path. This same image is what Render builds and runs — no Render-specific build config, no compose, no nginx sidecar, no Postgres.
- **Host = Render, bare `*.onrender.com`.** No custom domain. The free web tier is 512MB and spins down after ~15 min idle (~50s cold start on the next hit); both are accepted for a demo URL a judge clicks a handful of times.
- **Sweep disabled on the host.** A config flag (e.g. `SWEEP_ENABLED=false` / `SWEEP_INTERVAL_SECONDS=0`) must *short-circuit the loop*, not just lengthen the interval. The hosted instance is a static replay; nothing needs to reassess on a timer, and a spun-down free instance can't run a timer reliably anyway.
- **Hosted LLM backend = fake, no key.** `FakeLLMClient` serves every hosted request (zero spend, full UI). Real Claude reasoning text is **pre-baked into the seed**, not generated live.
- **Seed fixture is a replayable `demo_seed` with baked reasoning.** One real Haiku run ([[0008-tech-stack]]'s `anthropic` SDK, ticket-08 model tier) generates the diagnosis / justification / escalation strings once; they are committed into the seed script. The fixture is regenerated from a fresh real run at **D-2**, so the demo shows genuine model output without a live key. This also subsumes the "one real Haiku run before submission to confirm prompts parse and read well" check — that run *is* the fixture generation.
- **Hosted DB is ephemeral, re-seeded on every boot.** No volume, no `DATABASE_URL` persistence. The seed pre-bakes both narrative beats — a **human override** and a **Policy Engine rejection** — so they're visible without anyone mutating state. `DEMO_READONLY` gates the write-capable UI controls off on the host.
- **The live-trigger beat is local-video only.** Showing the agent react to a fresh event in real time happens in the recorded walkthrough against a local instance, not on the read-only hosted URL.
- **No `LocalLLMClient`.** The offline-verification client floated in the 2026-09-01 handoff is dropped — the baked seed fixture plus the one real Haiku run cover both the demo and prompt verification. The architecture doc gets one sentence noting a local/Ollama client is a possible seam, nothing more.
- **Schedule: skeleton now, one clean redeploy at D-2.** One-port collapse, Dockerfile, and the Render service skeleton land now while there's slack to fall back from; the seed fixture is regenerated and the final image redeployed once at D-2.

**No change to [[0008-tech-stack]]'s webhook tunnel.** Real-Razorpay dev stays exactly as recorded — ephemeral `ssh -R` tunnel, re-registered in the Razorpay dashboard each session, `FAILED_PAYMENT` only. The handoff's "Phase 2" (a named Cloudflare Tunnel / reserved ngrok domain for a stable webhook host) is **dropped**, since the real-Razorpay surface is frozen at the failed-payment slice and isn't being demoed live.

**Consequences**:

- **The hosted URL is a fixture, and the submission text should say so plainly** — "live read-only demo; full agent loop and live-trigger behaviour in the video and on a local run." Presenting the static instance as a live autonomous agent would be the same category of overclaim [[0014-flat-incentive-response-learnable-deferred]] guards against for the learning narrative.
- **512MB is a real ceiling.** The `anthropic` SDK is imported by `app/llm.py` regardless of backend; confirm the image boots and serves under 512MB before relying on the free tier, or budget for the paid tier.
- **Cold start is judge-visible.** First hit after idle waits ~50s. Options if that's unacceptable: a keep-warm ping, or the paid always-on tier. Not solving it is a valid choice for this audience — just a known one.
- **`demo_seed` now has two consumers with different needs.** The walkthrough seed still tunes `recovery_budget` and case ordering per [[0014-flat-incentive-response-learnable-deferred]]; the hosted seed additionally must be self-contained (both narrative beats pre-materialised, no interaction required). Keep both as the same script with a flag, not a fork, and keep either path away from the evaluation harness's canonical `MerchantConfig` / `DEFAULT_DATASET_SEED` — letting a demo or host seed reach an eval run is still a regression against [[0007-evaluation-integrity]].
- **The baked reasoning strings are a dated artifact.** They reflect the ticket-08 model and prompts as of the D-2 regeneration; if prompts change after that, the fixture is stale and must be regenerated.
- **Run instructions now document three paths**: local `uv` + `npm` dev, `docker run` (install-nothing), and the live URL. The README's `uv`/`npm` quickstart stays the primary path; Docker is the fallback.
